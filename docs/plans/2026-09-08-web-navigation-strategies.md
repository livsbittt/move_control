# 웹 탐색 방법과 실행 시간 제어

## 적용한 범위

목표 선택과 목표까지의 경로 계산을 구분한다. 목표 선택은 정보량 우선
(`frontier size / route length`), 가까운 곳 우선 (`1 / route length`),
지그재그 영역 순회를 제공한다. 목적지까지의 경로는 공통 A*를 사용한다.
안전 여유를 확보한 후보가 우선하며 전략 선택으로 최소 여유를 낮추지 않는다.
기존 정체 복구·후퇴 제한도 유지한다.

전체 제한 10–3600초, 이동 정체 제한 10–600초를 웹에서 입력한다.
정체 제한은 전체 제한 이하여야 한다. 기본 입력은 600초 / 90초다.
새 실행은 정지 상태에서만 시작한다. 실행 중 시작 요청은 기존 예산을 갱신하지 않는다.
중단 후 다시 시작해야 새 예산이 생긴다.

## 제어 경로

`POST /navigation/start` JSON `{strategy, duration_s, stall_s}`를 검증한 뒤
`session:<JSON>`을 `/wander/cmd`에 전달한다. HTTP 202는 전달 결과이며,
웹의 적용 결과는 노드가 발행한 `/navigation/session`으로 표시한다.
상태가 1.5초 이상 오래되면 시작을 비활성화한다. 교정 완료·비상 정지 해제·정지
상태를 HTTP와 주행 노드에서 확인한다.

Wander 노드의 독립 STEADY_TIME 시계와 0.1초 타이머가 예산을 소유한다.
ROS `/clock` 정지, Gazebo 배속 변경, 브라우저 종료에 영향을 받지 않는다.
전체 예산에는 지도 대기·회전·회복 시간이 포함된다. 소프트웨어 타이머이므로
정확한 밀리초 단위 정지 보장은 아니며 안전 게이트의 정지 지연도 별개다.

정체 시간은 신선한 최종 `/cmd_vel`의 직진 성분과 신선한 odom 위치로 갱신한다.
한 번의 연속 이동에서 2cm 이상 변위가 필요하다. 순수 회전으로 기준점이 움직여도
갱신하지 않는다. 정지·회전으로 끊긴 2cm 미만의 짧은 이동들은 합산하지 않으므로
반복 미세 동작에서는 보수적으로 일찍 정지할 수 있다. 같은 구간 왕복을 완전히
구분하는 탐색 진척도 지표는 아니며 전체 시간 제한이 별도로 유지된다.

만료 시 `/goal/cmd=stop`, 기존 `/cmd_vel_raw`에 0 명령을 발행한다.
최종 모터 출력은 여전히 안전 게이트만 담당한다. 자동 재시작은 하지 않는다.
웹은 적용한 방법, 경과·남은 시간, 정지 사유를 표시한다.
기존 실행 버튼은 별도 접힌 영역에 시간 제한 없는 실행으로 표시한다.

## 검증과 남은 범위

- 순수 로직 457 통과, 1 건너뜀. 기존 웹 JS 검사 24 통과.
- HTTP·Wander·GoalNode ROS 검사는 아래 실행 기록에 결과를 남긴다.
- 실제 브라우저 → HTTP → 실제 WanderNode에서 가까운 곳 우선 선택과 적용 확인,
  브라우저 종료 후 정지 확인. ROS 시각은 전 과정 0이며 목표 명령부터 정지 명령까지
  관측된 실제 시간은 약 10.13초다.
- 이 웹 실행 시험은 domain 229의 합성 준비 상태이며 모터·Gazebo 물리 모델이 없다.
  캡처는 웹 제어 검증 화면이다. 실물 정지 거리나 알고리즘별 전체 맵 완성 시간을
  입증하지 않는다. 이전 좁은 통로 탈출 및 전체 지도 완성 HOLD는 해소되지 않았다.
- 도착 예상 시간은 기존 경로 길이/속도 추정이다. 이번 전체 시간 예산과 다르며,
  회전·대기·복구를 포함한 정확한 완료 시간 예측은 아니다.
