# Pinky 지도 기반 탐색과 영역 주행

기존에는 goal_node가 계산한 지도 경로를 실제 wander_node가 소비하지 않았다.
지도 탐색과 지그재그 영역 주행을 기존 속도 소유자인 wander_node에 연결한다.
안전 노드만 최종 `/cmd_vel`을 발행한다.

## 모드와 조작

- `start`: LiDAR 기반 벽 회피 주행.
- `explore`: 지도에서 미탐색 경계를 선택하고 안전한 경로를 따라간다.
- `coverage`: 알려진 이동 가능 영역의 지그재그 경로를 따라간다.
- `stop`: 주행 정지, 경로 취소. 비상정지 해제는 별도 사용자 조작이다.

웹의 지도 기반 주행 버튼은 `/wander`로 명령을 보낸다. 지도·지도 좌표의
로봇 위치·활성 매핑·해제된 비상정지가 필요하다. 상태에 경로 대기,
위치 대기, 장애물, 도착, 진행 정체의 이유를 표시한다.

## 정지 조건

경로 없음/만료, 지도 좌표 변환 없음/만료, 장애물, 경로에서 과도한 이탈은
속도 0이다. 지도 경로 모드에서 측정된 위치/각도 진전 없이 명령만 반복되면
정지 상태를 유지한다. 센서 주행은 같은 구역에서 복구 3회 이후 정지한다.
짧게 앞뒤로 움직이거나 전진 명령을 보낸 사실만으로 실패 기록을 지우지 않는다.

지도 초기화는 SLAM과 탐색/영역 주행 기록을 함께 초기화하고 정지한다.
도달할 수 없는 영역은 방문 완료로 세지 않는다. 경로 생성에 실패하면
과거 경로를 계속 쓰지 않고 빈 경로로 취소한다.

## 실행

기존 bringup, ADC, 안전/센서/wander/web, SLAM이 실행 중인 실물 환경에서
추가로 `ros2 launch move_control goal.launch.py`를 실행한다. 새 goal_node는
정지 모드로 시작한다. 이미 실행 중인 노드를 중복 실행하지 않는다.
대시보드에서 모드를 선택해야 이동 요청이 발생한다.

테스트는 경로 추종, 안전한 경로 끝점, 취소/만료, 복구 제한, 지도 초기화,
UI 시작 조건을 검증한다. 격자 방문 기록은 실제 청소 면적 측정이 아니며,
실제 바닥에서의 회피·영역 주행 성능은 별도 관찰이 필요하다.
