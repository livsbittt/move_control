# 저장 지도 기반 위치 복구

- 별도 워크트리 `codex/map-relocalization`; 기존 매핑 세션과 Gazebo domain 13은 유지한다.
- 저장 지도는 map_server가 제공하고 AMCL만 map→odom을 소유한다. SLAM 매핑과 동시에 실행하지 않는다.
- 라이다와 지도 일치도, 추정 공분산, 관측/TF 신선도를 함께 검사한다. 위치 불명은 최종 safety gate에서 정지하고 goal_node의 경로를 폐기한다.
- 반복되는 불일치는 AMCL 전체 지도 재탐색을 요청한다. 정지 중에도 새로운 라이다 관측으로 필터를 갱신한다. 확신이 부족하면 정지를 유지한다.
- 기존 매핑 모드의 기본 동작은 유지하며 저장 지도 모드에서만 localization_required를 활성화한다. 저장된 보정값을 덮어쓰지 않는다.
- Gazebo domain 228/partition pinky_localization228에서 이동 및 순간 위치/방향 변경을 시험한다. odom은 순간 이동을 반영하지 않고, Gazebo 정답 위치는 오차 측정에만 사용한다.
- 검증: 순수 정책 테스트, 안전 게이트/경로 정지, 초기 위치 획득, 이동 중 추정, 순간 이동 후 복구, 센서 중단 시 정지, 지도 파일 해시 불변. 결과와 한계는 별도 증거 파일에 기록한다.

## 완료

- 정지 상태 AMCL의 후보 부족을 실제 Gazebo에서 확인하여 전역 지도/라이다 후보 검색과 세밀한 보정을 추가했다. 경쟁 후보가 비슷하거나 로봇 반경을 확보하지 못하면 사용하지 않는다.
- 신선한 관측 10개 확인, TF 유효성, 비동기 탐색 중 지도/odom 변경 검사, 손실 시 명령 캐시 폐기, 경로 재생성을 적용했다.
- 최종 Gazebo 실행과 289개 테스트, 패키지 빌드가 통과했다. [검증 결과](../validation/localization-2026-09-08/README.md).
- 사용자의 후속 요청에 따라 다른 domain 13 / 227 시뮬레이션도 종료했다. 작업 파일과 지도는 보존했다.
