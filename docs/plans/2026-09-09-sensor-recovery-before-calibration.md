# 보정 전 센서 초기화와 복구

## 목표와 현재 증거

사용자 요청: 센서 오류를 자동 보정 전에 발견하고 초기화할 수 있어야 한다.
2026-09-09 실기에서 BNO055 노드는 존재했지만 `/imu_raw`가 없었다.
기존 드라이버는 리셋 직후 통신하고 오류 레지스터를 무한 대기했다.
노드 목록 정상은 센서 정상의 증거가 아니다. I2C 주소 0x28의 응답 실패는
드라이버 수정 및 빌드 성공과 별개로 복구 여부를 검증해야 한다.

## 순서

`STOPPED -> SENSOR_CHECK -> RECOVERING -> STABILIZING -> CALIBRATING -> READY`

- 센서별 최신 timestamp, 수신 빈도, 값 범위와 품질을 확인한다.
- IMU는 칩 ID 0xA0, 읽기 성공, 정상 quaternion, 중력/gyro 범위를 확인한다.
- 보정 중 센서가 끊기면 즉시 속도 0, 보정 실패. 복구가 기존 보정을 성공으로 바꾸면 안 된다.
- 재초기화 후 최소 5초의 정상 데이터와 기존 stationary baseline 검사를 모두 통과해야 한다.
- 복구 동작은 보정 승인 또는 움직임 승인이 아니다. 기존 e-stop과 safety gate를 유지한다.

## 복구 단계

1. 센서 드라이버 종료와 파일 핸들 해제 후 재기동: 3회 이내, 2/5/10초 간격.
2. 계속 I/O 오류이면 정지/비상정지 및 전용 장치 소유권 확인 후 해당 버스만 복구.
   전체 ROS/모터 프로세스를 반복 재시작하지 않는다.
3. 장치 주소가 응답하지 않으면 ERROR_LATCHED. 자동 보정은 금지하고 오류 원인과
   시도 횟수, 마지막 정상 데이터 시각을 대시보드에 표시한다.
4. 원격 전원 제어가 검증되지 않은 센서의 전원 핀을 추정해서 조작하지 않는다.
   전체 로봇 재부팅은 자동 복구 기본 단계에서 제외한다.

## 권한과 책임

- 일반 ROS 프로세스: health 관측, 정지 요청, 드라이버 재시작 요청, baseline 검증.
- 제한된 root 서비스: 고정된 I2C0 장치만 복구. 임의 명령/경로 실행은 제공하지 않는다.
- root 복구 요청 전 센서 프로세스를 완전히 종료해야 한다. SIGSTOP으로 멈추면 열린
  `/dev/i2c-0` 때문에 sysfs unbind가 기다릴 수 있음을 실기에서 확인했다.
- 핀 기능/풀 설정을 저장하고 실패 경로에서도 복원한다. 상태 기록, 상호배제 lock,
  단계별 timeout, 재시도 예산을 갖추고 동시에 같은 버스를 초기화하지 않는다.
- ADC/배터리처럼 버스를 공유하는 장치는 모두 같은 복구 lock과 재개 절차를 사용한다.

## 구현 및 검증 상태

- 적용: Rosy OS BNO055 드라이버의 칩 ID 검사, CONFIGMODE 진입, 리셋 후 700ms 대기,
  단계별 timeout, read 실패 및 invalid quaternion 발행 차단, publisher lock 검사.
- 실기 적용: 기존 Pinky 패키지명 어댑터로 동일 C++ 코드를 빌드했다. OS 전체 교체는 아니다.
- 코드 분리: `bno055_device`가 장치 열기/초기화/읽기, `imu_sample`이 단위 해석과
  quaternion 검증, `main_node`가 ROS 발행과 상태 보고를 담당한다.
- 적용: `rosy-session-imu.service`가 IMU를 별도로 관리한다. 5초 간격으로 최대 3회
  실행한 뒤 실패 상태를 유지한다. `robot.launch.py start_imu:=false`로 중복 기동을 막는다.
- 초기화 로그: stage/open/probe/reset_wait/chip_boot/fusion_start/ready/stream과
  레지스터·실제 반환값·errno를 기록한다. 측정 상태는 `sensors/imu/status`로 보고한다.
- 오류 주입 검증: 주소 미응답, fusion 시작 실패, 측정 read 실패를 별도 ROS domain에서 재현한다.
- 미구현: 여러 센서를 통합하는 복구 coordinator와 제한된 root 서비스의 상시 운영 연결.
- 실기 확인: 기본 자동 soft reset을 제거한 드라이버 적용과 전원 재인가 후 IMU가
  약 100Hz로 수신됐다. 전용 서비스 재시작 뒤에도 20초 동안 2001개를 수신했고
  최대 간격은 약 20.3ms였다. 정상 수신 복구는 확인했지만 전기적 고장 원인까지 확정한 것은 아니다.
- 실기 확인: v4에서 모든 정지 센서 검사 및 3cm 왕복 2회 선형 검증이 완료됐다.
  IMU를 실제 중지한 일부 센서 모드에서는 최종 속도 5mm/s 제한과 약 9mm의 odom 이동을 확인했다.
- 회전 v5 적용: 보정이 별도로 더하던 5cm와 모든 빔 유효 조건 대신 최신 안전 게이트의
  동일 형상 회전 판정을 사용한다. 스캔 정렬은 관측 지지점과 후보별 겹침을 검사하며
  누락 빔을 가상 장애물 없는 공간으로 채우지 않는다. 실측 스캔 재생 검증은 통과했다.
- 미완료: 실기 회전 전체 검증과 이동 매핑. 22:26 보정은 외부 비상정지 입력으로
  중단됐고, 이후 별도 재시도는 현재 안전 게이트의 회전 공간 거부로 종료됐다.
  수동 보정 완료 상태와 실제 선형·회전 검증 완료를 구분한다.
