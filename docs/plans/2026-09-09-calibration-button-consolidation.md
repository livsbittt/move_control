# 대시보드 보정 버튼 정리 — 6개에서 3개로

2026-09-09 설계 합의. 아직 구현 전이다. 기준 파일은 작업 트리의 미커밋 상태이며,
`rosy_control/startup_calibration_node.py`와 `rosy_control/calibration_rotation.py`는
작성 시점에 다른 세션이 편집 중이었다. 구현 전에 해당 파일의 현재 상태를 다시 확인해야 한다.

## 문제

`web/dashboard.html`의 보정 카드에 버튼이 6개 있다. 개수 자체보다 **독립적인 두 축의 조합을
평평한 형제 버튼으로 늘어놓은 것**이 문제다.

- 축 A: 보정값을 새로 측정하는가, 저장된 설정값을 쓰는가
- 축 B: IMU를 포함하는가, 제외하는가
- 주행 가능 여부는 축이 아니라 **결과**인데 버튼 이름에 들어가 있다

그 결과 `IMU 제외 · 정지 센싱`과 `IMU 제외 · 제한 주행`이 나란히 서고, 운전자는 이름만으로
둘을 구분해야 한다. `4초 저속 이동 검증`은 `calibration_auto_motion` 기본값이 True라
실전 화면에서는 이미 숨겨져 있어 선택지로 세지 않는다.

## 확인한 제약

1. **회전 보정은 IMU를 필수로 요구한다.** `calibration_rotation.py`는 IMU yaw와 오도메트리
   yaw를 교차검증하는 것이 본질이며, IMU가 없으면 비교 대상이 없어 완주할 수 없다.
   따라서 "실패한 센서를 빼고 나머지로 보정을 완주"는 IMU 실패 시 성립하지 않는다.
2. **주행 필수 센서는 `lidar, odom, ir, us, tf`이다** (`configured_operation.py`).
   국지화를 쓰면 `map, map_tf`가 추가된다. 이 중 하나라도 빠지면 주행 권한이 나오지 않는다.
3. **제외 가능한 센서는 `imu`와 `camera`뿐이다.** `camera`는 애초에 required 집합에 없어
   주행에 영향이 없다. 따라서 센서별 제외를 9개 센서로 일반화해도 **실제 적용 대상은 IMU
   하나뿐이다.** 지금 일반화하지 않는다.
4. 인증서(`calibration_certificate.py`)에 저장되는 값은 병진 배율과 회전 결과뿐이다.
   **센서별 "기존 보정값"이라는 것은 저장되어 있지 않다.** "특정 값을 기존값으로 되돌린다"는
   현재 저장 구조에서 불가능하며, 실제로 가능한 것은 "해당 센서를 제외한다"이다.

## 설계

### 화면 구성

```
[보정 범위: 전체 측정 ▾]  [보정 후 위치: 머물기 ▾]
[ 전체 보정 ]  [ 부분 보정 · 실패 센서 제외 ]  [ 검증 중단 ]
```

1. `보정 범위` select를 신설한다. `전체 측정` / `이동·회전 생략(기존 설정값)`.
   없어지는 `use_existing_settings` 버튼의 역할을 여기서 흡수한다. 이로써 "측정하는가"와
   "센서를 빼는가"라는 두 축이 분리된다.
2. `보정 후 위치` select는 기존 `calibrationafter`를 그대로 둔다.
3. **부분 보정** 버튼은 하나지만 노드가 실패 센서 집합을 보고 분기한다.
   - `camera`만 실패 → 제외하고 전체 보정을 그대로 완주한다.
   - `imu` 실패 → 기존 설정값 + 저속 제한 + `rotation_verified: False`.
     현재 `limited_sensors` 경로와 같다.
   - 주행 필수 센서가 실패 → 버튼을 **비활성으로 두고 이유를 명시한다.**
     예: `라이다 실패 — 제외 불가(장애물 감지 필수). 전체 보정 재시도 또는 중단.`
     버튼을 숨기지 않는다. 위치가 고정되어야 하고 왜 안 되는지가 보여야 한다.
   - 실패한 센서가 없음 → 제외할 대상이 없으므로 비활성으로 두고
     `제외할 실패 센서 없음 — 전체 보정을 사용하세요`를 표시한다.
4. `sensing_only`, `use_existing_settings`, `use_limited_sensors` 버튼을 화면에서 제거한다.
5. `validate_motion`은 모드 선택 줄에서 빼고, `calibration_auto_motion`이 False일 때만
   phase 영역에 나타나는 컨텍스트 액션으로 옮긴다.

### 백엔드

6. 센서 등급을 상수로 명시한다. `EXCLUDABLE = ('imu', 'camera')`,
   `REQUIRED_FOR_MOTION = ('lidar', 'odom', 'ir', 'us', 'tf')`.
   등급표가 유일한 판단 근거이며 화면과 노드가 같은 표를 쓴다.
7. `sensing_only.py`와 `configured_operation.py`의 `['imu']` 하드코딩을 인자로 바꾼다.
   **인터페이스만 열고 일반화는 하지 않는다.** 통제는 6항의 등급표가 한다.
8. `partial_calibration` 커맨드를 신설한다. 분기 판단은 노드가 하며 화면은 의도만 보낸다.
9. `retry`에 범위를 붙인다. 기존 `retry:stay` 패턴을 확장해 `retry:<after>:<scope>`로 한다.
10. `web_node.py`의 커맨드 화이트리스트를 갱신한다.
11. 기존 커맨드 `sensing_only` / `use_existing_settings` / `use_limited_sensors`는
    백엔드에 유지한다. `safety/hazard.py`가 `abort`를 직접 발행하듯 화면 외의 경로가
    있을 수 있고, 제거는 이 작업의 범위가 아니다.

### 안전상 유지할 것

12. 부분 보정은 인증서를 발급하지 않는다. `calibration_verified: False`를 유지한다.
13. 제한 주행 속도 `linear .005 m/s` / `angular .05 rad/s`를 그대로 둔다.
14. 제외된 센서는 `excluded: True, eligible: False`로 보고한다. 정상으로 표시하지 않는다.

## 검증 계획

- 기존 dashboard JavaScript 테스트와 `test/test_calibration*.py`가 통과해야 한다.
- 실패 센서 조합별 분기를 테스트로 고정한다. camera 단독, imu 단독, imu+camera,
  필수 센서 포함, 실패 없음의 다섯 경우이다.
- 버튼 비활성 사유 문구가 실패한 센서 이름을 실제로 담는지 확인한다.
- 부분 보정 경로에서 인증서가 생성되지 않는지 확인한다.

## 범위 밖

센서별 보정값 저장(인증서 스키마 확장)은 하지 않는다. 운전자가 제외할 센서를 직접 고르는
체크박스도 하지 않는다. 둘 다 필요해지면 별도 작업으로 다룬다.
