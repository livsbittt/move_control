# 저장 지도에서 위치 추정과 복구

저장 지도 모드는 지도를 고정하고 AMCL이 `map → odom`을 보정한다. 바퀴 odom은 연속성을 유지한다. 로봇을 다른 위치에 옮겨도 저장 지도를 늘리거나 다시 그리는 방식으로 오류를 숨기지 않는다.

## 실행

기존 매핑/처리 스택을 먼저 종료한다. 센서·모터 bringup이 실행된 상태에서, 아래 통합 launch를 사용한다. `map.launch.py`/slam_toolbox와 동시에 실행하지 않는다.

```bash
ros2 launch move_control localized_robot.launch.py map:=/absolute/path/map.yaml
```

통합 launch는 safety와 goal에 `localization_required=true`, goal에 `static_map=true`를 전달한다. `localization.launch.py` 단독 실행은 위치 추정 서비스만 제공하므로 기존 주행 스택을 자동으로 보호 모드로 바꾸지 않는다.

기존 `robot.launch.py`, `goal.launch.py`의 기본 매핑 동작은 유지된다. 저장된 보정 YAML은 기존 순서로 읽으며 위치 추정기가 보정 파일을 쓰거나 파라미터를 덮어쓰지 않는다.

## 위치를 잃었을 때

1. 라이다 관측 시각의 `map → sensor` TF로 지도 일치도를 검사한다. 센서 장착 위치·방향은 TF에서 읽고, 유효하지 않은 회전값은 거부한다.
2. 관측 신선도, AMCL 공분산, 지도상의 벽과 자유 공간 일치를 함께 검사한다. 벽 뒤의 끝점만 맞는 후보는 배제한다. 지도 한 셀의 래스터 오차로 벽을 스치는 광선은 구분한다.
3. 위치가 불명확하면 `/localization/status` 권한이 즉시 해제된다. safety는 `/cmd_vel_raw`를 계속 받아도 최종 `/cmd_vel`을 0으로 만들고 이전 명령을 폐기한다. goal은 기존 경로를 폐기한다. 상태 메시지가 끊겨도 관측 시각 기반 권한은 만료된다.
4. 관측 불일치가 지속되면 지도 전체에서 위치와 방향 후보를 탐색하고 세밀하게 보정한다. 기기 반경과 센서 오프셋을 고려해 후보를 제한하고, 다른 위치의 경쟁 후보가 비슷하면 확정하지 않는다.
5. 탐색 중 지도 변경·들어 올림·odom 이동이 있으면 오래된 후보를 사용하지 않는다. 유일한 후보만 AMCL에 공급하고, 이후 새로운 라이다 관측 10개가 연속해서 확인해야 주행이 허용된다. 경로는 새 위치에서 다시 계산한다.

정지 중에도 AMCL의 `request_nomotion_update`로 새 관측을 처리한다. 일시적인 라이다 중단은 정지 사유이며, 관측이 복구될 때 유효한 필터를 곧바로 전역 초기화하지 않는다.

`config/localization.yaml`의 일치도·공분산·후보 차이 기준은 조정 가능한 초기 설정이다. 로봇 반경은 공유 설정과 저장된 보정 설정을 따른다. 지도 변경이나 완전히 같은 모양의 공간에서는 라이다만으로 위치를 유일하게 판별할 수 없으므로 정지를 유지한다.

## Gazebo 검증

```bash
bash tools/gz/run_localization.sh
```

ROS domain 228 / Gazebo partition `pinky_localization228`에 격리하며, 다른 실행이 같은 테스트 잠금을 사용 중이면 시작하지 않는다. 각 실행은 `/tmp/pinky-localization228/<시각>/`에 로그·측정값·소스 해시를 저장한다.

저장된 `map/calibrated_2026-09-08` 지도와 실제 Gazebo 라이다를 사용한다. Gazebo 정답 위치는 **오차 측정에만 사용**하며, AMCL·초기 위치·odom·TF에 전달하지 않는다. 시험 odom은 최종 안전 명령을 적분하므로 순간 이동을 따라 점프하지 않는다.

검증 범위는 초기 위치 획득, 직진·회전 중 추정, 위치/방향 순간 이동 후 복구, 위치 불명 중 계속 들어오는 주행 명령 차단, 경로 폐기/재생성, 라이다 중단/복구다. 대칭 지도와 실제 저장한 Gazebo 관측은 회귀 테스트에 포함했다.

Gazebo는 기존 속도 제어 플랜트를 사용한다. 실제 바퀴 미끄러짐, 센서 노이즈, RPi 탐색 처리 시간, 실물 들어 올림 감지는 별도 기기 검증이 필요하다. 이번 시험은 전체 자율 주행 FSM 대신 시험 명령 발생기와 실제 safety/goal/localization 노드를 연결한 검증이다.
