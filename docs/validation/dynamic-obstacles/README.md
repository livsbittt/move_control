# 동적 장애물 및 실제 Gazebo 지도 검증

현재 판정: **HOLD**. 장애물 추적·대기·정지 장애물 우회 연동을 구현했지만, 우회 후 전체 매핑 지속은 아직 검증 중이다. 실제 기기 적용 및 main 병합은 하지 않았다.

## 구현 범위

- LiDAR 스캔 시각의 TF로 odom 좌표계에 정렬한 후 연속 관측으로 정지·이동·불명을 구분한다. 분류에는 시간이 필요하며 물체 종류를 인식하는 신경망은 아니다.
- 카메라는 실제 Gazebo 렌더 영상에 기존 영상 분류기를 적용한다. 단안 영상에서 거리나 여유 공간을 추측하지 않는다. 카메라에만 잡힌 가까운 장애물은 거리 미확인 상태로 대기한다. 이 경우 자동 우회 성공을 보장하지 않는다.
- 정지 장애물은 원본 맵의 복사본에 임시 점유 영역을 추가해 우회한다. 추가 여유 거리는 안전 게이트와 공유한다. 기존 보정된 로봇 크기와 지도 벽의 여유 거리를 덮어쓰지 않는다.
- 움직임·불명 상태는 대기한다. 대기 중에는 주행 불능 시간 예산을 일시 정지하되 이미 소모한 예산을 초기화하지 않는다. 정지 물체에 대한 우회 회전도 최종 안전 게이트를 통과해야 한다.
- 센서 미래 시각·중복·오래된 관측은 유효기간을 갱신할 수 없다. 재관측은 분류 증거를 다시 수집하며, 가려진 물체는 실제 빈 공간 레이 증거 없이 삭제하지 않는다.
- 기울어진 스캔은 평면 추적 및 `/mapping/scan`에서 제외한다. 원본 `/scan`은 안전 게이트로 계속 전달한다. 가제보 IMU의 중력 성분도 몸체 자세에 맞게 투영한다. 이 보완의 실제 매핑 효과는 추가 검증 대상이다.
- 기능은 `obstacle_tracking_enabled` 기본값 false이며 검증 실행에서만 활성화했다. `/cmd_vel`의 단일 발행자는 계속 safety_node이다.

## 실제 실행 증거

| corrected, run `513022be08e046f8964543b81518c5bd` | 정지 58표본 중 정지 54, 불명 3, 미연결 1. 이동 구간에서 추적 미연결 43표본. 이후 몸체 기울어짐과 전방 LiDAR 무응답으로 sensor_hold. 미관측 53.55%, phantom 4.83%. **실패**. 실행 중 시간 배율 변경은 `realtime-adjustment.txt`에 기록했다. |
| velocity 진단, run `3a9ce06b2e004bd299ac3ee987e919bf` | 바퀴 구동 대신 속도 입력을 사용하는 원인 분리 실행. 179.9초, 총 이동 0.298m, 박스 제거 후 관측 경로 0.157m. 정지·이동 분류 및 대기 후 전진 재개를 확인했다. 이후 센서 보류가 회복됐지만 탐색 명령은 stop 상태로 끝났다. 미관측 56.14%, phantom 0%. **전체 매핑 실패**이며 바퀴 물리 검증을 대체하지 않는다. |

`baseline/track_map.yaml` 및 `diagnostic/track_map.yaml`은 실제 SLAM 출력의 PGM과 짝을 이루는 **부분 맵**이다. 원본 월드로 빈 공간을 채우지 않았다. `track_result.png`는 원본 벽과 실측 지도의 정렬 비교다.

원본 월드에는 외부에서 접근할 수 없는 폐쇄 영역도 있다. 전체 월드 관측률과 로봇이 접근 가능한 영역의 관측률은 별도 판정해야 한다. 단순 점 단위 연결성은 로봇의 통과 가능성을 증명하지 않는다.

가제보의 odom은 GT 어댑터, IMU는 GT 파생, IR은 합성, US는 LiDAR 파생이다. 렌더 카메라·LiDAR·바퀴 물리는 실제 시뮬레이션 입력이지만 물리 로봇의 센서 검증을 대신하지 않는다. 박스 GT는 시나리오 배치와 사후 평가에만 사용했다.

`obstacle-scenario.json.gz`는 원본 JSON을 손실 없이 압축한 파일이다. `python -m tools.gz.audit_obstacle_scenario <파일>`로 요약을 재생성할 수 있다. corrected 실행 후 추가한 분할 추적 보완·보정 여유 중복 제거·기울기 스캔 게이트는 해당 실행의 성공 증거로 간주하지 않는다.

## 남은 검증

- 수정본의 정지 물체 우회, 횡단·접근 물체 대기, 가림 후 재관측 및 주행 재개.
- 원래 탐색 경로 지속과 접근 가능한 영역 매핑 완료.
- 센서 보류가 회복됐을 때 사용자 중지·비상 정지를 구분하며 기존 탐색 의도를 유지하는 처리. 현재 보정 노드와 wander는 센서 보류에서 탐색을 중단하므로 자동 복귀가 보장되지 않는다.
- 이동 물체 제거 후 SLAM 지도 흔적: 현재 SLAM은 원본 스캔을 사용하며 동적 물체 제거 필터를 구현했다고 주장하지 않는다.
- 최신 실행의 코드 해시, 최종 맵·센서 영상·결정 로그와 테스트 결과를 함께 확정.

## 코드 검증

최종 코드의 순수 로직 테스트는 **524 passed, 1 skipped**, ROS 통합 테스트는 **56 passed**, Jazzy colcon 빌드는 **1 package finished**이다. ROS 테스트 로그는 `ros-tests-final.log`에 저장했다. 초기 동시 실행에서는 벽시계 기준 센서 유효시간이 지나 1~2개 테스트가 실패했으며, Linux 로컬 복사본의 최종 실행에서 56개가 통과했다. 시뮬레이션 실패를 이 테스트 통과로 대체하지 않는다.

실행: `RIG_OBSTACLE_SCENARIO=1 bash tools/gz/run_dynamic_validation.sh` (ROS 2 Jazzy 및 Gazebo 환경). 실행은 ROS domain 227 / Gazebo partition pinky_calmap227을 사용하며 동일 파티션의 중복 실행을 잠금으로 거부한다. 최종 검증 스크립트는 기본적으로 `RIG_REQUIRE_COMPLETE=1`이므로 부분 맵이면 실패한다. 원인 분석용 부분 실행은 명시적으로 `RIG_REQUIRE_COMPLETE=0`을 사용할 수 있다. 위 기록은 부분 실행의 결과다.
