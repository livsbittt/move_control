## 수정과 검증 범위

- 직진 전처리는 부채꼴 반경 대신 검증된 이동 궤적의 여유를 사용한다.
- 현재 보정 lease의 차체 외곽이 로컬 설정과 정확히 일치할 때만 외접 원을 실제 충돌 형상의 볼록 외곽으로 대체한다. 센서에서 차체 크기를 축소 추정하지 않는다.
- 이동·회전 혼합 명령은 최종 보정 및 제한된 속도로 검사한다. 센서 지연, 정지 지연, 회전 중심 오차, 시간 샘플 사이 최대 꼭짓점 이동을 여유에 포함한다.
- 짧고 단조로운 제자리 회전 기록은 같은 회전 중심을 검증하면서 반대로 회전해 복귀한다. 일반적인 곡선 후진과 혼동하지 않는다. 위치와 방향이 모두 맞아야 완료한다.
- 웹에는 현재 확인된 직진 여유와 제자리 회전 판정을 분리해 표시한다. 시뮬레이션 궤적 검사가 활성화되면 과거 원형 정지선을 실제 차단 기준처럼 표시하지 않는다.

실제 코너 LiDAR 720점은 `test/fixtures/mapping_corner_scan.json`에 보존했다. 동일 명령에서 원형 계산은 -1.5mm, 차체 외곽 계산은 오차와 지연 여유를 포함해 약 +20mm였다. 안전 게이트는 `/cmd_vel`의 유일한 발행자로 유지된다.

`a6ceaf6` 기준 순수 로직 527개 통과/1개 건너뜀, ROS 회귀 125개, 웹 회귀 26개 통과. 추가 관찰 도구는 실제 자세에서 월드 벽과 차체 볼록 외곽의 분리 간격을 계산한다. 샘플 사이 연속 충돌 부재나 실물 안전성까지 증명하지 않는다.

Gazebo LiDAR와 바퀴 동역학을 사용하지만 IMU/odom은 ground truth 기반, IR/카메라는 합성, 초음파는 LiDAR 기반이다. 실물 Pinky의 보정·센서·주행 승인을 대체하지 않는다.

V4 이후 원형 계획기에서 벗어난 자세를 위한 별도 직진 복구를 추가했다. 현재 방향의 차체 전체 translation extrusion을 장애물·미관측 셀 전체와 대조하고, 원형 계획기가 다시 시작 가능한 지점까지만 전진한다. 일반 XY 경로와 별도 의도로 전달하며 angular 명령은 0이다. 최대 누적 odom 이동 12cm, 30초, 명시적 탐색 시작당 한 번이며 재계획으로 예산을 갱신하지 않는다. 지도/TF/센서 상실, 형상 변경, 방향 이탈, 취소는 시도를 종료한다. 이 추가 변경의 실제 Gazebo 검증은 별도 후속 실행으로 기록한다.

V5 (`3428f10`)에서는 전진 복구가 선택됐지만 LiDAR 최종 궤적 검사가 이를 차단했다. 지도와 실제 스캔의 차이를 계획 단계에서도 반영해야 했다. `v5-forward-escape`에 720점 스캔과 전체 실행을 보존했다. 후속 수정은 안전 노드에서 최대 허용 스캔 지연을 포함한 전후 12cm 관측 한계를 제공하고, 지도와 LiDAR 양쪽에서 전체 구간이 확보된 방향만 선택한다. 후진도 방향을 유지하며 별도 직진 의도로 실행한다. 순수 로직 546개/ROS 회귀 129개 통과. 실동작 결과는 후속 실행에서 별도 기록한다.

V6 (`7535e8d`, `2c8993f9d6724a4fbe7ca3c589d65abf`)는 첫 직진 복구 완료 후 오른쪽 끝까지 이동했다. 373.66초, 2.853m, 7,477개 자세 샘플 최소 차체-벽 간격 33.36mm, 연결된 점 공간 미관측 23.73%였다. 다음 코너는 탐색당 1회 제한 때문에 복구가 차단됐다. 후속 변경은 성공 후 연속 odom 이동 25cm 및 모든 이전 시작점에서 25cm 이격을 확인할 때만 새 지역의 복구를 허용한다. 전체 탐색당 최대 4회이며 실패·좌표 점프·관측 단절은 재시도를 차단한다. 실행기의 신선한 완료 응답으로 종료하고 완료된 ID는 다시 움직이지 않는다. 순수 로직 550개, ROS 회귀 130개 통과. 후속 실제 실행 결과와 구별한다.
